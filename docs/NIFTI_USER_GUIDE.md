# 原生 NIfTI 使用指南（v0.1.0）

更新：2026-10-15。功能与验证边界见 [版本说明](V0_1_0.md)。以下是单 CT Finding / Entity 工作流；DICOM 的旧草稿与 PACS 操作不使用这套入口。

## 打开病例

访问部署站点的 `/nifti`。首页可按数据集、split、关键词选择已导入病例；ReXGroundingCT 的训练和验证数据通过 split 区分。显示数量是已导入数量，不是上游全量规模。

也可打开本地 `.nii` / `.nii.gz`，指定 CT、MR 或通用强度。普通原图入口支持三维 NIfTI-1 标量数据；原始和缩放后体素各不超过 512 MiB。空间单位不明确时需要明确选择，不能隐式猜测。CT 默认肺窗 1500/-600，但选择 CT 类型不会把任意强度转换为 HU。

服务器病例链接支持重开。本地尚未上传的文件刷新后仍需重新选择。ReX 四维标注用 [专用导入脚本](../deploy/datasets/rexgroundingct/IMPORT.md)，不要当作四维 CT 上传。CSV/JSON 清单只读取后端允许的根目录；具体挂载与路径以部署配置为准。

## 阅读报告与选择 Finding

- 右侧是 Finding / Entity 与图像信息两个标签页；报告原文和 Findings 是并列模块，中间可拖动调整高度。
- Finding 默认折叠，同时只展开一项。点击原文证据或 Finding 可联动；原文高亮尽量居中。
- Findings 标题右侧提供搜索与加号补充入口。点击类别名称旁的小箭头才打开类别修改菜单。
- 点击 Finding 会加载它的全部已保存 Entity mask；首个非空目标就绪后先定位，其余继续加载。空 Entity 不会因此分配一个完整 mask。
- 原文缺失时可在下方“其他功能”中补录。补录保存不会自动调用报告拆分模型。ReX Finding 描述不会拼接到原文栏；无法核实的证据不伪造高亮关联。

## 新增和编辑 Entity

1. 点击 Finding 行内的新增 Entity 图标，或已有 Entity 右侧的编辑图标，进入该 mask 的编辑状态。
2. 核对右上角当前 Entity 编号、名称和关联类别；一次只编辑一个目标。单纯选中或定位不等于进入编辑。
3. 顶部图像浏览工具与编辑工具分组显示。选择手工或 AI 编辑图标后展开对应工具下拉；hover 查看名称。浏览时编辑模式不保持高亮。
4. 手工模式使用画笔、橡皮等工具；需要完整体数据的操作会先补齐加载。
5. 右上角保存图标将修改保存为 mask 版本，保存后继续编辑。退出图标返回浏览，保留尚未保存的结果；退出不等于保存，刷新前应保存有价值的修改。

Entity 编号左侧的实线色块表示 mask 颜色；空心虚线表示空 mask，尚未加载的已保存 mask 有独立提示。选中 Entity 后再次点击名称可改名。定位、编辑、解除关联和删除是不同操作，解除关联不等于删除 Entity。

F1-E1 是 Finding 内的显示编号，删除后可以从 E1 重新排列，不是永久 ID。多个 Finding 可共享 Entity；当前 UI 不提供“选择共享 Entity”按钮。原始 ReX 名称中的 F/L 是来源通道和标签，不应把 L 解释为 lesion。

同一 Finding 的 Entity 使用一个多标签体积，不能互相覆盖；共享 Entity 在关联 Finding 中同步。保存和历史仍按 Entity 维护二值 mask 版本。

## 使用 nnInteractive

进入目标的编辑状态后，点击顶部 AI 图标，并在提示工具下拉中选点、框或涂画，设置包含/排除提示。在图像上添加提示，结果更新当前 mask；推理不自动代替保存。

“标注设置与提示管理”位于编辑工具组内，未进入编辑时禁用。可管理当前提示及应用方式：自动模式随提示变更推理；手动模式通过应用提示提交待处理变更。切换目标、重置或服务异常时不要把旧请求结果当作新目标结果。

当前部署模型在 rtx4500 GPU 推理。首个提示可能包含模型/原图准备和 seed 同步，耗时不等于纯 GPU 推理时间。提示历史不承诺跨页面刷新恢复。

## 保存、完成、结构和导出

- 保存图标在右上角状态区域。失败项保留未保存状态；版本冲突时先保留本地导出，再核对服务器版本。
- 标记完成位于左侧病例名右侧，属于病例操作。未保存编辑、空 mask 等会阻止完成；没有“不需标注 Entity”的界面豁免入口。修改标注后需要重新完成。
- 顶部“Mask 与文件”集中导入、导出和历史相关操作。历史恢复追加版本，不等于回滚整个病例；纯 NIfTI 不直接保存为 PACS DICOM-SEG。
- “图层与结构”管理显示及只读结构层。导入 TotalSegmentator 结果时需提供实际版本对应的整数标签映射；网格不匹配不会静默重采样。结构不创建 Entity，也不计入 Entity 标注完成条件。

## 加载和本地缓存

当前切片向上下持续加载至完整 CT。滚轮或 Finding 跳转会将待加载队列重排到新位置；只有当前显示目标尚未加载时才显示 loading。底部窗宽窗位与层数之间显示加载数量和百分比。当前病例加载完成后预加载后续两例。

当前 CT 和后两例共用 **512 MiB 压缩原图磁盘缓存**，不含 mask、提示或解码体积。当前图像优先，容量不足先淘汰旧历史，再淘汰较远预加载。超出预算时可能只缓存部分切片，其余正常走网络。

刷新或关闭页面不会主动清除磁盘缓存；重开有效的服务器病例会复用缓存并恢复最近切片。图像内容或几何变化后旧缓存/位置失效。浏览器清理站点数据、配额压力或隐私模式可能使缓存不可用；仍需要服务器元数据，所以不支持完全离线。

在顶部 **“Mask 与文件” → “清理本地图像缓存”** 操作，旁边显示占用/上限。清理保留已加载图像与当前标注，使在途旧写入失效，并停止当前页面后续预加载；刷新或打开病例后重新缓存。图像信息页还可查看缓存统计。

默认解码工作集预算 **1.5 GiB** 与上述磁盘预算是两回事：原图、mask 和操作临时缓冲使用工作集预算。关闭病例释放运行内存，不等于清空磁盘缓存。该预算不是浏览器进程总 RSS 或 GPU 显存上限。

## 故障处理

先确认访问的是预期部署和病例，再核对编辑目标与工具。模型异常检查服务状态；不要反复创建 Entity 代替重试。导入报网格错误需修正数据，不能靠改文件名解决。保存前刷新可能丢失未保存编辑，图像缓存无法恢复这些标注。

部署和回退见 [基础设施交接](INFRASTRUCTURE_HANDOFF.md)，本地开发入口见 [本地部署说明](../deploy/local/README.md)。服务地址、模型开关和数据挂载需以当前环境为准。
